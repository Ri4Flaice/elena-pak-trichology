# Рассылки Елены Пак

Служебное Next.js-приложение для персональных сообщений WhatsApp через GreenAPI.

## Локальный запуск на Windows

Нужны Node.js 24, npm и отдельная база PostgreSQL. Подойдёт установленный Postgres или база в Neon. Не используйте базу проекта `greenHouse`: у этого приложения своя схема и история рассылок.

1. Откройте PowerShell **в корне этого проекта**, где находится `package.json`. Проверьте `node --version` и `npm --version`.
2. Создайте `.env` из образца:

   ```powershell
   Copy-Item .env.example .env
   notepad .env
   ```

3. Заполните `.env`:

   | Имя                        | Что указать                                                                                                       |
   | -------------------------- | ----------------------------------------------------------------------------------------------------------------- |
   | `DATABASE_URL`             | Строку подключения к отдельной базе PostgreSQL. Для Neon её можно скопировать через **Connect** в панели проекта. |
   | `ADMIN_PASSWORD`           | Пароль входа на сайт, минимум 12 символов.                                                                        |
   | `SESSION_SECRET`           | Случайную строку длиной от 32 символов. Команда для генерации ниже.                                               |
   | `GREEN_API_URL`            | `apiUrl` **вашего** инстанса из кабинета GreenAPI.                                                                |
   | `GREEN_API_ID_INSTANCE`    | `idInstance` из кабинета GreenAPI.                                                                                |
   | `GREEN_API_TOKEN`          | `apiTokenInstance` из кабинета GreenAPI.                                                                          |
   | `GREEN_API_WEBHOOK_URL`    | Публичный HTTPS URL приложения с путём `/api/green-api/webhook`.                                                  |
   | `GREEN_API_WEBHOOK_SECRET` | Отдельный случайный секрет длиной от 32 символов.                                                                 |

   Секрет можно получить командой:

   ```powershell
   node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"
   ```

   Скопируйте результат в `SESSION_SECRET`. В файле `.env` значения записываются как `ИМЯ="значение"`; для GreenAPI используйте параметры из кабинета, а не пример другого инстанса. Если пока нужен только вход и предпросмотр Excel, три переменные `GREEN_API_*` могут оставаться пустыми. Для отправки они обязательны.

4. Установите зависимости и примените схему базы:

   ```powershell
   npm ci
   npm run db:migrate
   ```

5. Запустите сайт:

   ```powershell
   npm run dev
   ```

6. Откройте [http://localhost:3000](http://localhost:3000) и войдите с `ADMIN_PASSWORD`. Если порт 3000 занят, используйте `npm run dev -- -p 3100` и откройте `http://localhost:3100`.

Файл `.env` исключён из Git. После изменения переменных перезапустите `npm run dev`. Для проверки реальной отправки сначала используйте файл с **одним своим номером** и убедитесь, что инстанс GreenAPI авторизован.

## Работа с файлом

Загрузите `.xls` или `.xlsx` с листом `Клиенты` и заголовками `Фамилия`, `Имя`, `Телефон`. Файл читается в браузере; на сервер передаются только эти три поля и номера строк. Если установлен пароль на открытие, предварительно сохраните файл без пароля. Переименование расширения не преобразует формат файла. После подготовки шаблона `{{Имя}}` и `{{Фамилия}}` откройте предпросмотр, проверьте выбор клиентов и подтвердите отправку.

Перед созданием кампании отметьте подтверждённые согласия и укажите их источник. Согласия сохраняются по телефону; ранее отписавшиеся клиенты исключаются при каждом импорте и перед отправкой. В конец сообщения добавьте понятную инструкцию отказа, например: «Напишите СТОП, чтобы отказаться от сообщений».

Во время серии вкладка должна оставаться открытой. После серии или прерывания откройте сохранённую кампанию и нажмите «Продолжить». Сервер соблюдает общие ограничения на инстанс: 50 попыток в день, до 25 сообщений в серии, минимум 60 секунд между сообщениями и 30 минут после серии; рабочее время 10:00–18:00 `Asia/Qyzylorda`. Значения хранятся в `SenderState`, интерфейс получает их с сервера; старые `SEND_BATCH_SIZE` и `SEND_DELAY_MS` больше не используются.

«Принято GreenAPI» означает постановку сообщения в очередь, а не подтверждение доставки. Фактические статусы поступают по вебхукам; следующее сообщение допускается после подтверждения отправки предыдущего. Нет подтверждения пять минут — остановка для ручной проверки. Неопределённые результаты автоматически не повторяются. «Повторить ошибки» подготавливает только подтверждённые повторяемые отказы, отправка запускается отдельно.

Первоначальная настройка, обновление существующей базы и проверка: [GREEN_API_SAFETY.md](GREEN_API_SAFETY.md).
